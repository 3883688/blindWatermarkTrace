## 建议指标门槛

- 缩放加随机裁剪专项：裁剪区域不小于原缩放图 50% 时，正确召回率建议 >= 95%，错误命中率 = 0。
- 小面积截图专项：裁剪区域 30% 时，正确召回率建议 >= 80%，错误命中率 = 0；若达不到，需要明确标注支持边界。
- 未加水印误报：首轮至少 1,000 张同来源/同风格/相似构图图片，误报率 < 0.1%；商用上线前建议扩大到 10,000 张，误报率 < 0.01%。
- 随机 trace 稳定性：同一测试集连续 20 轮不同 trace，关键指标方差应可解释，不允许只在单个 trace 下通过。
- 置信度：所有追溯结果必须输出置信度、命中模式、关键 vote/score，并用独立验证集校准阈值。

## 测试体系升级

1. 扩展攻击矩阵：已覆盖 JPEG 30/50/70/90、二次 JPEG、旋转 1/3/5/10 度、模糊、锐化、中值降噪、浏览器/微信截图模拟、噪声和屏幕拍照模拟；还需补真实微信/浏览器保存链路与真实手机拍屏样本。
2. 扩展样本矩阵：照片、插画、UI 截图、低纹理图、高纹理图、纯色/渐变背景、不同分辨率和不同长宽比。
3. 增加误报集：未加水印原图、同来源相似图、同风格图、经过同样攻击处理的未加水印图。
4. 增加多轮 trace：每张图至少生成 20 个不同 trace，统计均值、P5/P50/P95、最差样本和最差攻击组合。
5. 产出固定格式：JSON 明细、CSV 明细、Markdown 摘要，保留失败图片和检测响应，便于回归。

## 算法改进方向

1. 阈值校准：用误报集反推阈值，避免只追求召回率导致错误命中。当前多级 fallback 应统一输出内部 score，建立统一置信度模型。
2. 几何鲁棒性：对裁剪、缩放、轻微旋转增加同步模板或特征点辅助配准，降低对固定 tile 扫描尺度的依赖。
3. 冗余编码：对小截图水印码增加纠错码和跨尺度重复布局，减少单个 tile 弱信号导致的漏检。
4. 攻击自适应预处理：检测前根据输入估计缩放、压缩、锐化/模糊程度，选择对应的滤波和扫描尺度。
5. 误报防护：对所有频域命中增加二次验证，例如 trace pattern、checksum、空间一致性和多窗口投票同时达标才返回 trace。
6. 可观测性：检测响应中保留 method、votes、score、candidate_count、threshold、fallback_order，报告可定位失败原因。

## 必须优先修复的问题

1. 未加水印图片误报：检测链路必须默认保守，无法满足多重证据时返回“未检测到”，不能返回相似 trace。本轮抽样已达到 0/20，后续要扩大负样本规模验证。
2. fallback 顺序：视觉匹配、局部截图命中、小截图频域码等 fallback 必须有严格候选边界和二次校验，避免用弱相似度直接归因。
3. 置信度含义：置信度必须绑定多重证据，例如 votes、特征匹配、残差一致性；不能只由单一频域 vote 推导。
4. 召回恢复：在误报和错 trace 维持为 0 的前提下，下一步需要继续改进 0.5 倍缩小后低像素区域的漏检问题，并扩展 JPEG、旋转和二次压缩攻击验证。

## 工程改进方向

1. 把商用基准脚本纳入 `pytest` 或 CI 的 nightly job；快速 PR 测试只跑小矩阵，发布前跑全矩阵。
2. 将测试输出目录固定为 `test_output/` 并加入清理策略，避免污染生产 `uploads/` 和 `data/`。

4. 把支持边界写入产品说明：最低分辨率、最小可追溯截图面积、支持/不支持的攻击类型和置信度含义。
5. 对数据库记录和本地 JSON 记录增加测试隔离开关，避免测试 trace 进入生产数据。

## 2026-07-10 画质与安全联合基线

本轮在“未经程序嵌入的图片不得归因到具体 trace”优先级高于召回率的前提下，增加了画质扫描、商用门禁、逐轮统计、1,000+ 负样本生成能力和统一 PowerShell 入口。

### 已完成改进

- 新增 PSNR、SSIM、MAE、RMSE、最大像素差和 P5/P50/P95 统计。
- 新增保真度扫描和 Pareto 配置选择，不再固定使用 `fidelity_level=0.75`。
- 缩放裁剪基准支持环境变量矩阵、固定随机位置、20 进程检测、逐例耗时和 `PASS/FAIL` 门禁。
- 攻击基准增加逐轮召回、误报、错误 trace 和吞吐统计。
- 负样本生成从 6 类扩到 10 类，默认规模提升到 1,000，并记录命中模式和内部证据。
- 禁止 `detect_by_residual_match` 仅凭视觉/残差相似度返回具体 trace；残差只保留为候选证据。
- 将局部码和主码检测的视觉一致性校验前移。视觉候选为空时不再执行昂贵窗口扫描，且最终归因条件没有放宽。

### 画质结果

原配置 `fidelity=0.70-0.90`、局部截图层 `high/1.0` 的最差画质只有 PSNR `32.576-36.063 dB`、SSIM `0.871961-0.911184`，不满足低损伤目标。逐层消融表明主要损伤来自高密度满强度 `small_crop_trace`，其次是 `code` 层。

将配置改为 `fidelity=1.0`、局部截图层 `medium/0.35` 后，5 张图无攻击预筛结果为：

- 最差 PSNR：`40.617 dB`。
- 最差 SSIM：`0.954281`。
- 无攻击正确追溯：`5/5`。
- 对应原图误报：`0/5`。
- 结论：达到当前 `38 dB/0.95` 硬底线，但没有达到 SSIM `0.98` 理想目标，只能作为候选配置，不能直接设为生产默认值。

### 缩放裁剪结果

在安全移除残差单证据归因后，候选配置对 2 档缩放、3 档裁剪、每组合 1 个固定位置的两轮随机 trace 测试中，正确召回在 `33.33%-46.67%` 之间，错误 trace 为 0。首轮同步的 30 个未加水印原图变体误报为 0，但召回远低于整体 95%、30% 裁剪 80% 的门槛。

把局部截图强度从 `0.35` 提高到 `0.50` 没有改善召回，证明继续损伤图片不能解决当前检测问题。成功案例全部来自强视觉一致性路径，局部频域码没有形成稳定恢复。随机 trace 变化会显著改变召回，当前短码方案不满足运行稳定性要求。

### 负样本与性能结果

旧基线 255 个负样本曾出现 4 个“残差验证命中”，误报率 `1.57%`。残差单证据归因已被禁用并有快速回归测试覆盖。

新的 120 个合成负样本加 55 个原图攻击变体测试在 20 进程下运行 20 分钟仍未完成，并留下 5 个同源原图攻击命中工件。由于进程超时前没有完成 JSON 汇总，这 5 个工件只能作为阻断性风险证据，不能作为正式误报率统计。定向复测 5 个工件并行 5 分钟仍未完成，说明负样本最坏路径延迟也不符合在线服务要求。

### 当前结论

当前版本为 `FAIL`，不得宣称达到商用通用标准：

1. 画质候选达到当前硬底线，但未达到理想 SSIM 0.98。
2. 安全模式下缩放裁剪召回只有 33.33%-46.67%。
3. 短码对随机 trace 不稳定，提高强度无效。
4. 扩展负样本测试出现未完成的疑似误报工件，且最坏检测延迟超过 5 分钟。

### 下一阶段算法升级

1. 用带 BCH/LDPC 或 Reed-Solomon 纠错和认证标签的 48-64 bit 码替换当前 16 bit 短码。未经校验的短码只能生成候选，不能归因。
2. 增加同步模板和尺度估计，先恢复 tile 尺度与相位，再解码；避免用几十万滑动窗口暴力扫描。
3. 建立两级索引：低成本全局特征先缩小候选集，只有候选通过内容一致性后才运行频域码解码。
4. 将检测设置可计算预算：限制最大候选数、窗口数和总耗时；超出预算返回“未检测到/需要离线深度检测”，不能无限扫描。
5. 新码版本必须并行保留旧版本读取能力，但新生成图片只使用通过画质与负样本门禁的版本。
6. 完成新码后重新运行 5 轮完整攻击、完整缩放裁剪和 1,000 负样本；通过后再扩大到 10,000 外部真实负样本。

## 2026-07-10 几何对齐认证检测实测与升级边界

本轮实现并启用了受 5 秒预算约束的几何对齐认证检测。检测先用 ORB/RANSAC 将查询图配准回登记图片坐标，再只在已知 robust tile 位置聚合完整 64-bit 码证据。视觉匹配和残差匹配只能缩小候选范围，不能单独返回 trace；旧密集扫描仍默认关闭。

### 画质强度边界

固定 `fidelity=1.0`、`small_crop_trace=medium/0.35`，对 5 张图片扫描独立 robust strength：

| robust strength | 最低 PSNR | 最低 SSIM | 最大像素差 | 质量硬门禁 |
| ---: | ---: | ---: | ---: | --- |
| 0.75 | 40.905 dB | 0.956965 | 12 | PASS |
| 1.0 | 40.498 dB | 0.952704 | 12 | PASS |
| 1.5 | 39.517 dB | 0.942456 | 13 | FAIL |
| 2.0 | 38.513 dB | 0.929061 | 13 | FAIL |

因此 `1.0` 是当前同时满足 `PSNR >= 38 dB`、`SSIM >= 0.95` 的最强档位。API 和商业基准默认 robust strength 已统一为 `1.0`；不得通过升到 `1.5/2.0` 换取召回，因为这会违反 SSIM 硬门禁。

### 60 案例缩放裁剪结果

- 配置：5 张图片，缩放 `0.5/1.5`，裁剪 `0.3/0.5/0.8`，每组合 1 次固定随机裁剪。
- 正样本：正确 `12/30`，召回 `40.00%`，错误 trace `0/30`。
- 负样本：未加水印原图同矩阵误报 `0/30`。
- 按缩放：`0.5` 为 `60%`，`1.5` 为 `20%`。
- 按裁剪：`30%` 为 `10%`，`50%` 为 `60%`，`80%` 为 `50%`。
- 12 个成功案例全部来自“几何对齐 64-bit 认证水印”。
- 全部 60 案例检测延迟：P50 `3.001s`，P95 `4.648s`，最大 `6.740s`。

结果继续判定为 `FAIL`。虽然没有错误归因，但召回低于此前安全模式最高 `46.67%`，且最大延迟超出 5 秒在线预算。不能通过放宽 bit error、允许短码归因或恢复残差单证据来提高表面召回。

### 下一版代码格式要求

现有 robust 载荷是 16-bit magic 加 48-bit trace hash，没有可承担裁剪/缩放随机错误的纠错冗余。下一版必须新增版本化 ECC 格式，建议采用 BCH 或短块 LDPC，并满足：

1. 同步、纠错、认证分层：同步信息只用于定位，ECC 解码结果仍需完整认证标签确认后才能归因。
2. 多 tile 交织：相邻 bit 分散到不同空间 tile，避免一次裁剪破坏连续码段。
3. 唯一候选原则：多个候选通过认证时返回未检测到，不做相似度猜测。
4. 预算内失败：超过候选数、窗口数或总耗时立即返回未检测到，离线深度检测使用独立显式入口。
5. 画质回归：任何新格式必须继续满足最低 PSNR `38 dB`、SSIM `0.95`，并以 SSIM `0.98` 为优化目标。
6. 商用验收：先通过 5 轮快速矩阵，再经用户确认运行 1,000+ 负样本；最终上线前使用独立外部数据完成 10,000 负样本测试。

本轮没有启动预计耗时较长的 1,000 负样本和完整多轮攻击测试，因为快速矩阵已经未通过召回门禁。应先完成 ECC 新格式，再投入长测资源。

## 2026-07-10 三相 RS v2 实现与快速门禁结果

已实现实验性 `RS(24,8)` 三相 robust watermark v2，并保持生产缺省版本为 v1。v2 使用 `reedsolo==1.7.0`，每个 tile 仍写入 64 bit，三个相位合计构成 192-bit RS 码字；新记录显式保存版本和 codec，旧记录继续走 v1。v2 不允许回落到模糊 v1 检测，多个候选通过时仍返回未检测到。

### 安全补强

标准 RS 解码按 `0/2/4/6` 个低置信度 erasure 有界尝试。实测发现三相拆分会减少每相的空间重复，导致无攻击样本也可能超过 8 个错误 symbol。RS 失败后只允许与当前已完成内容对齐的候选记录比较完整 192-bit 预期码字，最大接受 32 bit 错误。该半径的随机码接受概率约 `5.68e-22/候选`，严于 v1 `4/64` 半径约 `3.68e-14/候选`；它不能用于全库搜索或候选发现。

### 画质扫描

固定 `fidelity=1.0`、`small_crop_trace=medium/0.35`：

| v2 robust strength | 最低 PSNR | 最低 SSIM | 无攻击追溯 | 原图误报 | 结果 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1.00 | 40.186 dB | 0.949203 | 5/5 | 0/5 | FAIL |
| 0.95 | 40.144 dB | 0.949661 | 5/5 | 0/5 | FAIL |
| 0.90 | 40.154 dB | 0.949668 | 5/5 | 0/5 | FAIL |
| 0.74 | 40.815 dB | 0.957077 | 5/5 | 0/5 | PASS |

`0.90-1.00` 经整数舍入后 robust 像素改变量大多仍为 `2`，SSIM 改善很小；`0.74` 跨过量化边界后改变量降为约 `1`，因此被选为 v2 画质候选。

### 60 案例快速矩阵

- 正确追溯：`3/30`，召回 `10.00%`。
- 错误 trace：`0/30`。
- 未加水印误报：`0/30`。
- 按缩放：`0.5` 为 `20%`，`1.5` 为 `0%`。
- 按裁剪：`30%` 为 `0%`，`50%` 为 `0%`，`80%` 为 `30%`。
- P50/P95/最大检测延迟：`3.133s / 6.761s / 7.263s`。
- 三个成功样本的 bit error 为 `29/25/30`，全部使用候选专属码字距离确认；标准 RS 解码没有形成成功案例。

v2 同时未通过召回 `>46.67%` 和 P95 `<=5s` 的提升门禁，因此 `ROBUST_WATERMARK_VERSION` 继续缺省为 `1`。v2 仅通过显式环境变量 `ROBUST_WATERMARK_VERSION=2` 用于后续实验，不运行 1,000 负样本和完整多轮攻击长测。

### 后续架构判断

三相方案的主要问题是把同一 payload bit 的空间重复次数降低到约三分之一，RS parity 没有抵消载体相关错误。下一版不应继续增加相位或提高强度；应保持每个 payload bit 的全图重复，同时通过相位间 carrier permutation、软合并或独立的低损伤同步层提供多样性。任何新方案仍必须先通过同一 60 案例安全门禁。

## 2026-07-10 全重复 HMAC64 v3 快速门禁结果

v3 已按“每个 tile 完整重复 64-bit”实现，不再拆分 payload。候选码由 `HMAC-SHA256(WATERMARK_AUTH_KEY, robust-v3:trace_id)` 截取 64 bit 生成；三个 tile phase 只改变逻辑 bit 到物理 carrier 的 permutation。检测完成几何对齐后，对每个 tile 做 median 归一化和 `[-3,3]` 离群裁剪，再逆 permutation 软合并。v3 最大允许 8 个 hard bit error，随机 64-bit 码落入该半径的概率约 `2.78e-10/候选`。

### v3 工程安全

- v3 生成要求至少 32-byte 的 `WATERMARK_AUTH_KEY`，缺失或过短返回 HTTP 503。
- 记录保存 16 hex 字符的 `robust_auth_code`，保证密钥轮换后旧记录仍可检测。
- v1/v2/v3 独立分派；v3 不进入 dense v1 模糊检测。
- 多个候选同时通过仍返回未检测到。
- 生产 `.env.example` 继续设置 `ROBUST_WATERMARK_VERSION=1`，v3 仅在商业基准中显式启用。

### v3 画质

配置：`fidelity=1.0`、`small_crop_trace=medium/0.35`、`robust v3 strength=0.74`。

- 最低 PSNR：`40.759764 dB`。
- 最低 SSIM：`0.957292`。
- 无攻击追溯：`5/5`。
- 原图误报：`0/5`。
- 画质和完整图门禁：`PASS`。

### v3 60 案例结果

- 正确追溯：`16/30`，召回 `53.33%`，高于 v1 安全基线最高 `46.67%`。
- 错误 trace：`0/30`。
- 未加水印误报：`0/30`。
- 缩放 `0.5/1.5`：均为 `53.33%`。
- 裁剪 `30%/50%/80%`：`30% / 80% / 50%`。
- P50/P95/最大延迟：`2.933s / 4.610s / 5.927s`。
- 16 个成功样本 bit error 分布为 `0,0,6,0,0,3,0,1,1,1,6,1,4,0,8,0`。
- 所有 5 张源图均有成功案例，每张正确 `3-4/6`，没有单张图片完全失效。

v3 首次同时超过 v1 整体召回基线并满足 P95 5 秒、零错 trace 和零快速负样本误报，但没有通过商用分项门禁：30% 裁剪要求 `>=80%`，50%/80% 裁剪要求 `>=95%`。因此结果仍为 `FAIL`，不提升生产默认，也不启动长测。

### v3 后续改进边界

1. 不提高 8-bit 认证半径；若要调整，必须先建立至少约 3,000 个独立负样本的阈值校准集。
2. 不提高 `0.74` 强度；当前画质已通过，应优先改善同步和软权重。
3. 优先记录失败样本的未通过 bit error、phase 覆盖和 alignment 质量，区分 carrier 错误与几何误差。
4. 对 permutation 软合并研究按 phase、纹理和缩放可靠度加权，但所有权重必须固定后再用独立验证集验收。
5. 达到裁剪分项门禁后，再由用户确认运行 20 轮随机 trace、完整攻击和 3,000+ 负样本。

## 2026-07-10 内容特征候选索引修复

真实截图 `111/2.png` 暴露出候选检索缺陷：截图长宽比从原图 `1.776` 变为 `1.499`，正确记录按长宽比排序落到第 `161` 名，而在线只验证前 8 条。直接对正确记录执行 ORB/RANSAC 和 v1 解码可得到 957 个内点、`0 bit error`，证明失败发生在候选检索而非水印恢复。

已完成以下修复：

- 新生成记录缓存最多 768 个缩放后 ORB 描述符到 `data/feature_index/<record-id>.npz`。
- 查询图片只计算一次描述符，以 ratio-test 内容匹配数和质量排序候选。
- 内容强匹配要求至少 12 个 good match；内容分数只用于候选排序，不能归因。
- 服务重启或旧记录缺少索引时，仅回填最近 4 条记录，并保留最近 2 条候选槽位，避免无界扫描。
- 无内容索引或内容证据不足的记录继续按长宽比排序。
- pytest 强制使用独立 `test_output/pytest_false_positive_gate/` 路径，防止测试 trace 再次写入生产 `data/images.json`。

真实回归中，正确记录从第 `161` 名提升到第 `1` 名，内容 good match 为 `360`、质量 `0.46875`；完整提取返回 `TR-08EAA8637AFC478D`，v1 解码 `0 bit error`。

同时修复了两个与候选索引叠加的前置性能问题：原图排除检查改为先读图片头尺寸、同尺寸才解码；文件指纹改为生成时保存文件/像素 SHA256，提取时只比较记录字段，旧记录不再逐文件重新哈希。真实 HTTP API 总耗时从约 `32.8s` 降到 `2.524s`，其中对齐认证约 `1.99s`。历史测试记录仍保留在生产数据中，未做自动删除或破坏性清理。

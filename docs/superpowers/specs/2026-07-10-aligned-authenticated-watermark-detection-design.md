# 几何对齐与认证水印解码设计

## 目标

在不增加当前水印嵌入强度的前提下，提高缩放、裁剪和轻度旋转后的正确追溯率，并缩短未加水印图片的检测时间。任何归因必须包含完整 48-bit 水印载荷、魔数、CRC 和登记 trace 一致性；16-bit 短码、视觉相似度和残差相似度只能生成候选。

## 方案选择

采用“特征匹配估计几何变换、对齐到登记图片坐标、在已知 tile 位置解码完整认证码”的方案。暂不修改已有嵌入格式，避免同时引入新编码、数据迁移和检测逻辑三类风险。若该方案仍无法达到门槛，再单独设计带 BCH/LDPC 或 Reed-Solomon 的新水印版本。

## 检测流程

1. LSB 完整载荷和块级载荷保持现有快速路径。
2. 从登记记录中按全局视觉特征生成少量候选，默认最多 8 个。
3. 对每个候选使用 ORB、KNN ratio test 和 RANSAC 计算查询图到登记水印图的单应矩阵。
4. 要求至少 18 个内点、内点比例至少 0.32，并验证单应矩阵可逆、投影面积和覆盖率合理。
5. 将查询图和有效区域 mask 投影到登记水印图坐标，保持登记图的缩放后坐标系。
6. 根据记录中的局部水印密度和登记图缩放比例计算已知 tile 位置，只解码有效覆盖率至少 70% 的 tile。
7. 每个 tile 解码完整码分数，执行重复位恢复、魔数、CRC 和登记 payload 距离校验。
8. 只有多个空间分离 tile 对同一完整 payload 达成一致，且与候选 trace 完全一致时才返回具体 trace。
9. 完整码不足时返回 404。短码命中、视觉匹配或残差匹配不能单独返回 trace。

## 组件边界

- `align_query_to_record(image, record)`：读取登记水印图，计算单应矩阵，返回对齐 RGB 图、有效 mask 和几何证据。不负责水印判定。
- `iter_aligned_small_trace_tiles(aligned, mask, record)`：根据嵌入密度产生有效 tile，不读取数据库。
- `decode_authenticated_aligned_trace(image, records)`：聚合完整码证据并返回内部候选结果，不构造 API 响应。
- `detect_aligned_authenticated_watermark(image)`：调用候选解码，校验 trace，构造现有响应格式。

这些函数保持独立，便于用合成单应变换和伪造短码分别测试几何与认证逻辑。

## 安全门禁

- 仅视觉一致、仅残差一致、仅短码一致时必须返回 404。
- 完整码必须通过魔数和 CRC，并匹配唯一登记 trace。
- 至少两个空间分离 tile 通过完整码校验；单 tile 不允许归因。
- 候选 trace 之间没有唯一胜者时返回 404。
- 单应矩阵退化、覆盖率不足、文件缺失或解码异常均作为候选失败，不回退到弱归因。

## 性能预算

- 候选上限默认 8 个。
- 每个候选只检查登记 tile，禁止密集滑动窗口作为在线默认路径。
- 记录候选生成、对齐和解码耗时，以及检查 tile 数。
- 在线检测预算目标为单图 P95 小于 5 秒。超过预算时停止后续候选并返回 404；离线深度检测可由后续独立接口实现。

## 接入顺序

新对齐认证检测器放在精确 LSB 失败之后、现有密集局部码扫描之前。验证通过后，在线链路默认关闭密集扫描；旧扫描只保留在商用 benchmark 或显式离线模式中。视觉匹配和残差匹配继续作为内部候选证据，不直接归因。

## 测试与验收

- 单元测试：恒等、0.5/1.5/2.0 缩放、30%/50%/80% 裁剪、轻度旋转的单应对齐。
- 安全测试：未加水印原图、同源攻击图和伪造短码不得归因。
- 回归测试：现有 27 个测试全部通过。
- 快速矩阵：2 档缩放、3 档裁剪、每组合 1 个固定区域，错误 trace 和负样本误报必须为 0，正确召回必须高于当前 46.67%。
- 扩展矩阵：快速矩阵提升后再运行完整缩放裁剪、5 轮随机 trace、16 类攻击和 1,000 负样本。
- 画质：本方案不修改嵌入像素，候选配置继续保持最差 PSNR 40.617 dB、SSIM 0.954281 的基线。

## 失败边界

如果完整码在几何对齐后仍无法稳定恢复，不通过降低 CRC、减少完整码位数或允许单 tile 命中解决。该结果说明现有嵌入码容量和信噪比不足，下一步必须升级新水印版本和纠错编码。
